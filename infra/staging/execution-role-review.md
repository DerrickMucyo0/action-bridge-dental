# Staging IAM and execution-role review

Prepared locally for account `631367363628`, Region `us-east-2`, stack
`actionbridge-dental-staging`. All artifacts are **unapplied drafts**. No AWS login,
account API call, IAM or resource change was made. The owner-reported 153-resource
inventory is incomplete and does not certify production isolation.

## Names and separate principals

[resources.json](resources.json) fixes exact names for the five functions, five
runtime roles, table, two queues, upload bucket and five log groups. Runtime roles
are under `/actionbridge/staging/actionbridge-dental-staging/`, with names equal
to the function name plus `-role`. Their boundary policy names equal the function
name plus `-boundary`. No generated-role suffix or guessed prefix is used in the
staging execution drafts. All names need collision checks before creation.

The CloudFormation role remains
`arn:aws:iam::631367363628:role/actionbridge-dental-staging-cfn`, trusted only by
`cloudformation.amazonaws.com` through unchanged
[cloudformation-trust.json](cloudformation-trust.json).

- The preparer can create/review only the two named change sets, pass only this
  execution role to CloudFormation and upload only staging artifacts. Its explicit
  execution deny means a separately authorized executor is required.
- The execution role provisions resources, not treatment processing. It passes
  only the five exact runtime roles to `lambda.amazonaws.com`.
- Each runtime role trusts only Lambda and receives its own least-privilege
  policies intersected with its own administrator-owned boundary.
- Only an independent authorized administrator provisions or changes the boundary
  policies, execution policies or deployment principals. Neither the execution
  role nor developer can manage their own privileges.

## Restricted API lifecycle

The backend API ID is generated by AWS and remains unknown locally. Management
ARNs have no account component, so Region or API name alone cannot identify the
new API. Never grant regional `/apis/*` writes.

1. Review/apply the bootstrap-only execution draft separately. It allows POST on
   the Ohio API collection only with the exact name and disabled-endpoint request
   condition; GET metadata reads are allowed for newly generated IDs. Existing-API
   writes and other Regions are denied. It supplies no IAM, storage, runtime or
   identity creation rights. Recovery deletion needs a separate exact-ID review.
2. The bootstrap template adds only logical ID HttpApi, ProtocolType HTTP, the
   exact name and a disabled execute-api endpoint. No routes or stage are created.
3. After separately authorized bootstrap execution, verify the actual ID from
   the new stack and generate the local backend execution review bundle using
   that ID. Syntax validation does not establish account ownership.
4. Remove bootstrap collection creation rights before the same-stack backend
   UPDATE. The generated backend preserves the raw API's ProtocolType and name.
   Reject any API replacement/import and unrelated resource changes.

Import/reimport requires its action-specific API verb combinations. API-name
conditions cover CreateApi but do not secure the current import/reimport path;
API tags do not prove authorization for every child. Backend policy scopes GET,
PATCH, PUT, POST and DELETE to the verified API root and reviewed
routes/integrations/authorizers/stage paths. It denies POST/PUT on the collection.
No custom domains, VPC links, separate deployments or API Gateway credentials role
are needed by this template.

## Backend execution bundle

[build-execution-policy.py](build-execution-policy.py) emits a new local directory
only with a supplied ten-character API ID. It refuses existing output directories
and symlinks. Its review.json explicitly records `ownership_verified: false` and
`execution_permissions_boundary: false`.

The complete exact-ARN action matrix exceeds a single managed-policy quota.
Therefore the generator splits valid identity policy documents into parts no
larger than 6,144 compact characters. The accompanying explicit-deny guardrail
parts are required too. **These parts are identity policies, not a permissions
boundary.** An administrator must review/attach all parts together, protect them
from deployment-principal mutation and exclude any unrelated attached policies.
The generator refuses a bundle exceeding the default ten managed policies per
role. It never attaches or simulates policies against AWS.

| Scope | Execution permissions and restrictions |
| --- | --- |
| Five exact runtime roles | Paired-boundary CreateRole/PutRolePolicy/trust and constrained policy attachment; necessary reads/tags/deletion for rollback; exact PassRole to Lambda |
| Five exact function ARNs | Create/read/update/delete/tags; API permission mutation only on four HTTP handlers, principal restriction where supported |
| Worker event-source mapping | All actions require exact Ohio worker FunctionArn; Get/Delete permit AWS's observed Resource `*` cleanup shape; Update additionally requires a regional mapping ARN (optional captured UUID narrows Update further). Missing FunctionArn remains denied. See [mapping repair](MAPPING_CLEANUP_REPAIR.md). |
| Exact staging table | Create/read configuration/update/delete/TTL/tags; no item access or scans |
| Exact staging upload bucket | Create in Ohio; owned-bucket metadata/configuration/deletion only; no object reads/deletes or bucket policy/ACL mutation |
| Exact artifact bucket/prefix | Owned GetObject and bucket location only; no artifact writes or bucket creation |
| Two exact queues | Create/read configuration/update/delete/tags; no messages, purge or processing |
| Five exact log groups | Configuration/tags/deletion only; DescribeLogGroups is regional metadata read; no log-content reads or writes |
| Captured API ID | Only reviewed root/child paths; no collection create/import, production APIs or tag-path wildcard assumptions |

Guardrails deny IAM operations outside the five roles, wrong paired boundaries,
boundary removal/version changes, mutations outside exact staging selectors and
business-data/model/processing/Cognito access. CloudFormation cannot modify its
own role, the caller, networking or unrelated infrastructure. Exact-name collision
findings remain essential: a name is not ownership evidence.

Actual regional provider read-back/rollback behavior remains unverified. A denied
provider call must be reviewed under the same exact scope, never solved with
AdministratorAccess or full-service permissions. Narrow the mapping ARN to its
captured UUID after creation. CAPABILITY_NAMED_IAM is required for backend UPDATE.
